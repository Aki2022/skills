# own-pptx-build コンテンツ評価ループの設計方針

## Purpose

own-pptx-build のコンテンツ評価ループに必要な評価段階、評価者の役割、入力範囲、合格条件、コスト管理を定める。評価は成果物の品質改善を支援するが、人間が判断する制作ゲートの代わりにはならない。

## Problem

- テキストと画像の各段階で、読み手に伝わる内容かを評価する必要がある。
- 審査員だけの反復は防御的な追記を増やし、読みやすさを損なうおそれがある。
- 評価者数・対象サイズ・モデルによって利用量が大きく変わるため、入力範囲と実行回数を制御する必要がある。

## Goals

- base.md、outline.md、mockup、preview の各段階で内容品質を評価できるようにする。
- 採点して合否を決める審査員と、採点せず理解のしやすさを見る初見読者を分ける。
- 不合格箇所の再設計を助けるアドバイザーを、評価者とは別の役割として定める。
- 段階ごとの入力範囲、モデル、合格条件、回数上限とコスト見積りを一貫して扱う。

## Non-Goals

- 評価結果で人間の判断ゲートを置き換えること。
- 画像段階の合成デッキ評価を廃止すること。

## Domain Language

| Term | Meaning |
| --- | --- |
| 審査員（judge） | rubric で採点し、verdict と must_fix を出す評価者。ループの合否判定に使う。 |
| 初見読者（fresh reader） | 予備知識なしで対象だけを読み、理解可否と素朴な疑問を返す評価者。採点はしない。 |
| アドバイザー（advisor） | 不合格箇所の修正時に構成案を出す設計者。評価ループの合否には参加しない。 |
| フレッシュ評価 | 過去版や過去評価の文脈を与えない新しい評価者による評価。 |
| seen 書き出し | 画像検分で判定より先に、実際に見える主図解と要素数を記述すること。 |

## Actors and Scenarios

- orchestrator: 評価計画を提示し、評価者を起動し、結果を集約して修正方針を示す。
- 評価者: 審査員、初見読者、アドバイザー、画像検分を担う。
- 人間: 評価計画を承認し、制作上の人間ゲートを判定する。

## Requirements

### Functional

- **計画承認**: 各評価の前に対象、評価者の構成と人数、モデル、回数上限、概算トークン数を提示する。承認前に評価を実行しない。workstream の Authorization Envelope に事前承認された計画があれば、個別の確認を省略できる。
- **評価者の構成**: 審査員と初見読者の2役で評価する。初見読者が本編について「分からない」としたスライドがあれば、must-fix として扱う。アドバイザーは不合格箇所の修正フェーズに限って使い、構成案3つ、推奨案1つ、その根拠を出す。
- **モデルと既定値**: モデル、合格条件、最大回数は `own-pptx-build/style-guide/skill-config.json` を実行時の正典とする。計画承認時に上書きする場合は変更後の条件を提示する。
- **コスト見積り**: 概算トークン数は、評価者数 × 回数 ×（対象サイズ × 1.5 ＋ 出力10k）を目安に提示する。
- **合格条件**: `contentEval.passThreshold` の各条件を全て満たす。審査員ごとの下限、平均点の下限、重大 must-fix の上限、初見読者の「分からない」枚数の上限を個別に判定する。
- **再評価と収束**: 再評価は毎回フレッシュな評価者で行う。前回の must-fix 反映確認に必要な事実のみ審査員に渡せる。最大回数は `contentEval.maxRounds` に従う。追加の反復は人間承認と再見積りを要する。前巡から指摘が減らない場合は、設定された収束規則に従い人間へエスカレーションする。
- **画像検分**: 画像の判定前に seen を書き出す。seen がない画像検分の ok は無効とする。

### Quality

- **読者評価の対象**: 読者評価には、その段階で読み手が実際に受け取る成果物だけを渡す。base.md 段階は base.md、outline 段階は outline.md、画像段階は画像のみとし、画像評価に Markdown 文書を併給しない。
- **一致検査との分離**: VLM 構図比較、数値監査、画像検分などの一致検査には、照合に必要な outline、mockup、base.md の該当節を渡してよい。一致検査は読者評価を代替しない。
- **自足性**: outline は本文、構図メモ、出典を含み、単独で読者評価できる内容にする。
- **可読性**: 審査員と初見読者は、内容に加えて表現と読みやすさも評価する。mockup 由来の文字の乱れは、ネイティブテキストへ置き換える工程があるため評価対象外とする。

## Source-of-Truth Boundaries

- `own-pptx-build/references/content-eval.md` は評価計画、実行、判定、記録の手順を定める。
- `own-pptx-build/style-guide/skill-config.json` はモデル、閾値、回数上限の実行時既定値を定める。
- `own-pptx-build/SKILL.md` はパイプラインの概要と詳細手順への案内を担う。

## Constraints and Tradeoffs

- 評価者を増やす、対象を広げる、反復を増やすほど利用量が増える。計画承認時に対象範囲と回数を明示する。

## Visual Theme

- 信頼性・公共性・中立性。派手さより明快さ。誰にとっても分かりやすい「わかる」デザイン。
- 情報は詰め込みすぎず、余白で優先順位を示す。

## Color Roles（役割のみ。値は未定 = ゲート後）

- Primary: 行動・リンク・主要アクション。
- Text / Background: 高コントラストの本文可読性を最優先。
- Semantic: success / warning / error / info を色 **と** 記号/テキストの併用で伝える（色のみに依存しない）。
- Data viz: 系列色は意味を持って一貫。色覚多様性に配慮。

## Typography

- 和文は Noto Sans JP、等幅は Noto Sans Mono を前提（OFL。**フォントファイルは同梱せず**、環境/Webフォント参照）。
- 見出し/本文/注釈の明確な階層。本文は十分な行間で CJK 可読性を確保。

## Spacing / Layout

- 一定単位の spacing スケールで余白を統一。整列基準を1つに。
- グリッドベースのレイアウト。情報密度を抑え、視線導線を明快に。

## Components

- ネイティブ要素優先のアクセシブルなコンポーネント（フォーム・ボタン・テーブル・ナビ）。
- 状態（フォーカス/エラー/無効）を明示。

## Iconography

- Material Symbols 由来のアイコンを参照可（Apache 2.0）。意味の明確なものを最小限に。

## Motion

- 過度なアニメーションを避け、`prefers-reduced-motion` を尊重。

## Accessibility

- WCAG AA を基準（コントラスト 4.5:1 以上等）。キーボード操作・ランドマーク・代替テキストを担保。
- 公共サービスとして、幅広い利用者・支援技術での利用を前提にする。

## Content Tone

- 平易で中立な日本語。専門用語は補足。断定より事実と根拠。

## Do / Don't

- Do: 明快・高コントラスト・一貫・余白・根拠の明示。
- Don't: ロゴ/紋章の使用、公式資料と誤認される表現、色のみでの情報伝達、過剰な装飾。

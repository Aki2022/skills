# ルーブリック — <対象名>

呼び出し側がこのテンプレを埋めて評価者へ渡す。**アンカー文**を書く（点をつける根拠を文章でなくアンカーへの
一致で決めさせる — lp-review）。公式配点がある提出物は満点をそのまま写す（content-eval）。

## 観点と配点

| # | 観点 | 満点 | 4（満点近く）のアンカー | 2（境界）のアンカー | 0 のアンカー |
| --- | --- | --- | --- | --- | --- |
| 1 | <例: 第一印象> | 10 | <実在の企業サイトと見分けがつかない> | <整っているが AI 生成と分かる> | <崩れている> |
| 2 | … | | | | |

## 合格ライン（thresholds.json に写す）

```json
{ "judgeMinEach": 75, "judgeAvgMin": 80, "criticalMustFixMax": 0,
  "freshReaderUnclearMax": 0, "reviewFindingsMax": 0, "reviewMaxSeverity": "minor" }
```

## ペルソナ（審査員・初見読者は別 subagent）

- 審査員: <実読者から逆算。例: 15年選手のアートディレクター／外部選考委員／事業法務 DD>
- 初見読者: 予備知識ゼロ・過去版を知らない。採点せず「分かる／引っかかる／分からない」と素朴な疑問だけ返す

## 渡すもの・渡さないもの

- 渡す: 成果物（その段階で読み手が受け取る形・単独）、本ルーブリック、`carry`（前巡 must-fix の反映確認・却下済み提案）
- 渡さない: 設計意図・仕様書・過去版・過去評価の本文

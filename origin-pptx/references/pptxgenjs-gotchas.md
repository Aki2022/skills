# PptxGenJS 落とし穴集（③ネイティブビルド）

2026-07-10 の24枚デッキ通し（PptxGenJS）で実際に踏んだもの。ビルドスクリプトを書く前に一読すると
無駄な反復（ビルド失敗・レンダリング後の手戻り）を避けられる。実証済みヘルパは
`scripts/deck_helpers.js` に集約済み——まずそれを土台にするとここの罠は最初から回避される。

> **座標系の注記（2026-07-13 v3改訂）**: §3・§7・§9 の下端clip系の数値は **v2キャンバス
> （720×405pt）時代の実測値**。v3は **960×540pt** で、フッター類は deck_helpers v3 の
> `defineSlideMaster`（日付/ページ番号 y=512.8・下揃え、test3.pptx実測）に集約済みのため
> 各スライドで手置きしない。本文・注記・出所の最下端は **y≤500**、source は y=496（ヘルパ既定）。
> v3キャンバスでの soffice clip 境界はまだ実測していない——初回デッキの④で日付欠けが出たら
> ここに新値を記録すること。

## 1. `ShapeType` はインスタンス側にある

`pptx.ShapeType.roundRect` は動くが、モジュール/クラス側の `P.ShapeType` は **undefined**。
`const P = require("pptxgenjs")` の `P.ShapeType.rect` で「Cannot read properties of undefined」で落ちる。
必ず `const pptx = new P(); const ST = pptx.ShapeType;` として `ST.*` を使う。

## 2. `chevron` は左の切れ込みが左寄せテキストを食う

工程フローを `chevron` で作り、左寄せの日本語ラベルを載せると、シェブロン左の凹み（ノッチ）が
文字の先頭を隠す（「2026年9月」が「6年9月」に切れた実例）。ノッチ深さは図形の高さに比例するため
インセントを増やしても安定しない。**工程ステップは `homePlate`（左フラット・右尖り）か塗り `rightArrow`
を使う**。装飾目的で本当にシェブロンが要るときだけ、テキストをノッチ深さより右に十分寄せる。

## 3. フッター日付と出所の脚注が左下で衝突する

house style はフッター左下に日付、右下にページ番号。しかし内容スライドは左下に「出所:」脚注を置く
ことが多く、同じ左下で重なる（実際に7枚で重なった）。**出所は y≈374pt（フッターの一段上）に、
日付フッターは y≈392pt に置き分ける**。`deck_helpers.js` の `source()` / `footer()` はこの分離を実装済み。

## 4. 画像は必ずアスペクト比保持でフィットさせる

`addImage` に box の w/h をそのまま渡すと歪む。元画像の実寸（`file` で取得）から aspect=w/h を出し、
box に収まる側を基準に縮小して中央寄せする（`deck_helpers.js` の `imgFit(path, aspect, ...)`）。
スクショは細いグレー枠（`#DDDDE3`）を付けると背景と馴染む。

## 5. 実データチャートは「addChart＋ネイティブ・オーバーレイ」のハイブリッドで組む

実データチャートは**Excelで編集できるネイティブOOXML（`addChart`）が必須**。`addChart` が
表現できない装飾（系列末尾の国名/国旗ラベル・赤枠コールアウト・軸外注記・リーダー線）は、
チャートに求めず**ネイティブのテキスト/図形/小画像をチャートの上・横に重ねて**再現する:

- 外れ値の軸クリップ → `valAxisMaxVal`（超過系列はプロット領域で自然に切れる）
- 系列強調 → `chartColors`（強調1系列のみ赤/primary、他は同一tint）＋ `showLegend: false`
- オーバーレイ位置合わせ → `layout: {x,y,w,h}`（プロット領域を0-1で固定）を指定すると
  線端のy座標が `chartY + (ly + (1 - v/vmax) * lh) * chartH` で決定的に計算できる
- 編集可能性の決定的チェック → `unzip -l out.pptx | grep -E "charts/chart|embeddings"`

**チャートを画像化（SVG/PNG化）してよいのは、ユーザーがExcel編集可能性を明示的に放棄した場合のみ**
（2026-07-10: SVG全面画像で納品し「Excelで編集できなければならない」と差し戻された）。
詳細レシピは `chart-rules.md §2.5`。

## 6. レンダリング検証は決定的チェックを先に

`soffice --headless --convert-to pdf` → `pdftoppm -png` 後、(a) 豆腐化（フォント置換）、
(b) テキストのボックス外あふれ、(c) 要素個数、(d) 端の接触、(e) 欠落アセット列挙を先に潰す。
ビルドスクリプトは欠落画像を握りつぶさずログ出力させる（例: `missing[]` を最後に print）。
その後に VLM でモックアップ/意図と構図比較（敵対的プロンプトで差分列挙）。

## 7. LibreOffice レンダリング特有の罠（2026-07-10 実測）

soffice で PDF 化すると PowerPoint とはズレる挙動がいくつかある。プレビュー検証はこれ前提で見る。

- **フッターは y≤384pt に置く**。405pt キャンバスで y=392 以降に置いた小文字はグリフ下半分が
  クリップされる（全スライドで発生した）。日付・ページ番号は y384 程度に。
- **`ST.line` の矢じり（`beginArrowType`/`endArrowType`）は薄く/見えなくレンダリングされる**。
  可視の双方向矢印が要る図（例: TOBEの相互接続）は、線の両端に**塗りの三角ポリゴンを別途描く**。
  さらに矢じり先端をアイコン中心から少し引いて（padして）アイコン画像の下に隠れないようにする。
- **`homePlate`（右向き五角形）の右斜辺は縦中央付近でテキストを食う**（chevronの左切れの右版）。
  工程ステップに使うときは右マージンを広めに取り、長い行は短縮する。
- **ラテン＋CJK隣接で微小スペースが入る**ことがある（"DB化"→"DB 化"に見える）。実害は小さいが、
  気になるなら和文だけにするか改行位置を調整。
- **CJKは narrow なボックスで単語途中改行が起きる**（"ポート\nフォリオ"）。手動 `\n` で割るときは
  語の途中で割らない。自動折返しに任せるならボックス幅にフォントを収める。

## 8. 意味アイコンは Material Symbols・image_gen 産はイラストのみ（2026-08-27 改訂）

セマンティック・ラインアイコンは image_gen で生成せず **Material Symbols（wght300×opsz48）の
SVG を直接 `addImage`** する——取得・vocab_map 規約・再着色（`recolor_svg.py`）・濃色セルへの
**白 fill 直置き（白チップ不要）**・単一概念グリフの限界と対策は `references/material-icons.md` が正典。
旧方式の罠（白箱露出・淡線で normalize 2周・回収競合・焼き込み色）はこの置換で構造ごと消える
（A/B 実測 2026-08-27: ≈0 vs ≈4.4万トークン/個）。
**image_gen 産で残るのはイラスト（人物・いらすとや調・UIモック）だけ**で、これは
`scripts/normalize_icons.py --illustrations`（白背景透過のみ・再着色なし）を通してから埋め込む。
イラストを濃色セルに載せる場合の白チップは引き続き有効。詳細は `references/image_gen.md`。

## 9. フッターは y=386、本文・脚注の最下端は y≤370（2026-07-11 実測）

y=392 は soffice 描画で下端 clip して日付が欠ける（§3の旧値）。かといって y=380 まで上げると
本文下部の注記行と衝突するスライドが出る。**安全帯は y=386**（deck_helpers 修正済み）。
これを守るため、各スライドの本文・注記・source の最下端は **y≤370** に収める。
source（出所）は y=372 でフッターの1段上。

## 10. 吹き出しは標準 wedgeRoundRectCallout 単一オブジェクト＋adj後処理（2026-08-27 改訂）

吹き出しを roundRect＋尻尾三角＋白矩形の**3オブジェクト合成で作らない**。旧v3方式（2026-07-11
の描画順対処）は継ぎ目・浮遊三角が出やすいうえ、**後工程で人間が動かすと3つバラバラで負担になる**
（2026-08-27 ユーザー差し戻し。合成方式はレンダでも継ぎ目露出を実測）。
正解: PowerPoint 標準プリセット `ST.wedgeRoundRectCallout` を1オブジェクトで置く——人間は
黄色ハンドルで尻尾を直接ドラッグできる（SKILL.md の「標準プリセット図形を使う」原則の適用）。
尻尾位置は OOXML adjustment 値（adj1=中心からのX offset（幅比×100000）・adj2=同Y・adj3=角丸）だが
**pptxgenjs 4.0.1 は adj を公開しない**（rectRadius/angleRange の特殊ケースのみ）。このため
`deck_helpers.speechBubble()` は objectName に `speechBubble@adj1=..,adj2=..` とエンコードし、
必須工程 **`sanitize_pptx.py`（fix_callout_adjustments）が <a:avLst> へ注入**する。
sanitize を通し忘れると尻尾が既定位置（左下）のままになる—— `--check` が未注入の印を NG として
検出する。自作せず speechBubble() を使う（soffice レンダ＋sanitize --check で検証済み 2026-08-27。
PowerPoint 実機は次回デッキの④.5で確認する）。

## 11. チャート軸ラベルの箱幅はバーピッチに合わせる

バー間隔（ピッチ）22pt に幅 44pt のラベル箱を中央揃えで並べると、隣同士が 22pt ずつ重なって
文字が潰れる（「18歳以上」の1が消える等）。**ラベル箱幅 ≤ ピッチ** になるようバー間隔から先に
設計し、収まらなければフォントを 7pt まで落とすかピッチを広げる。`wrap:false` を併用
（1文字ずつの縦折返し化を防ぐ）。

## 12. 例示チャート（実データなし）は「空枠」ではなく「数値なしイメージ図」で描く（2026-07-11 差し戻し）

実データ捏造の禁止を「空のグレー帯プレースホルダ」で実装すると、**人間には未完成・作りかけに
見えて差し戻される**。②mockup 段階の空枠指定（imagegen-prompt-convention §11）はあくまで
mockup 用であり、③ネイティブビルドでは例示チャートを**ネイティブ図形のイメージ図**として描く:

- 積み上げ棒・横棒などの「形」はグレー系列（#404040→#7F7F7F→#BFBFBF→#D9D9D9）の rct で描く
- カテゴリラベル・凡例テキストは置いてよい（定性的な例示であり統計値の主張ではない）
- **数値・%・軸目盛りは一切描かない**＋パネル右上に小さく「イメージ」と明記
- 実データが本当にあるチャートは従来通り §5（addChart ハイブリッド）

## 13. 人物・キャラクターのイラストはバストアップ＋quality=high で生成する

512px・quality=low の全身イラストは、スライド上で 60-70pt に縮小されると表情が潰れて
「無個性なシルエット」に見える（「選べるキャラクター」を訴求するスライドで致命的だった）。
人物は **close-up bust portrait (shoulders up), large expressive face** をプロンプトに含め、
**quality=high** で生成する。スマホUIモック等の「密度が品質に直結するイラスト」も同様に high。

## 14. v3 新規則（2026-07-13 スタイル改訂に伴う追加）

- **クローム層は master 任せ**: 日付・ページ番号・縦書きコピーライトは deck_helpers v3 の
  `defineSlideMaster('HOUSE')` が自動付与する。各スライドで footer を手置きしない（二重表示になる）。
  コピーライトの縦書きは `vert: "vert270"` オプション（addText/masterのtext objects両対応）。
- **数字と単位は `numUnit()` で組む**: 単位=数字の50%サイズを別テキストボックスで置くと
  ベースラインが揃わない。同一 addText のラン配列（`[{text:"6,000",options:{fontSize:20}},
{text:"件/年",options:{fontSize:10}}]`）で混在させる。
- **改行は手動**: CJK の自動折返しは不自然な位置で切れる（§7とも関連）。本文・キーメッセージ以下の
  テキストは**文節境界に `\n` を明示**する。キーメッセージ自体は1行厳守（折返しさせない）。
- **valign/align を明示する**: カード見出し・数値・バッジは `align:"center"` / `valign:"middle"`、
  本文は `valign:"top"`。無指定のまま「なんとなく上寄せ」になっているのは v3 検収で差分扱い。
- **表は必ず `addTable`**: 罫線・セルを rct/line で模造しない（PowerPoint 上で表として編集
  できることが要件）。スタイルは tokens.json `table.*`。
- **フォントは全デッキ一律 BIZ UDPGothic**（2026-07-28決定）: `mk({font: "BIZ UDPGothic"})` で
  ビルドし、ビルド直後＋inject後の最終ファイルに `scripts/set_fonts.py <pptx>` を実行して
  全XML（テーマ・テンプレ部品含む）を統一する（冪等）。
  ※不採用フォントの経緯: **Meiryo**はmacOSでOfficeアプリ内バンドルにしか無くfontconfig=soffice
  から見えず④検証が代替描画になる（2026-07-13）。**Hiragino Sans W4＋Helvetica（mac/share
  2プロファイル制）**は、LibreOffice(CoreText)がウェイト付きフルネームを解決できず明朝化する
  うえ（2026-07-19実測）、PowerPoint実機でもW4が正しく解決されなかったため廃止（2026-07-28）。
- **背景を塗ったオブジェクトに枠線を付けない**（v3原則）。box/rct ヘルパは既定で線なし。
  枠線が要るのは塗りなしの注釈枠・警告枠（`speechBubble` 等）のみ。

## 15. pptxgenjs の `slideNumber` は使わない（修復トリガーとしては未確定・2026-07-13改訂）

`defineSlideMaster({ slideNumber: {...} })` は slideMaster / slideLayout / slide の3箇所に
`<p:ph type="sldNum" idx="4294967295"/>`（unsignedInt最大値）のプレースホルダを出力する。
当初これを修復エラーの原因と推定したが、**人間製の実ファイルに `type="dt" idx="4294967295"` が
あっても PowerPoint が普通に開ける反例を確認**——修復の真因は §16（チャートXML）と §17（負extent）
だった可能性が高い。ただし不正 idx であることに変わりはなく、リスクを抱える理由もないため
**方針は維持: slideNumber オプションは使わず、ページ番号・日付は `newSlide()` がスライド直描き**
（テンプレ注入=inject_template.py でレイアウトが差し替わっても保たれる利点もある）。
`sanitize_pptx.py` は検出時に情報表示のみ行う（検査失敗にはしない）。

## 16. pptxgenjs 4.0.1 のチャートXMLはスキーマ違反で PowerPoint 修復エラーになる（2026-07-13 実証）

折れ線（line）・散布図（scatter）・レーダー（radar）チャートで、pptxgenjs が `<c:ser>` に
**(a) `<c:invertIfNegative>`（bar/bubble専用要素）を混入**させ、**(b) `<c:marker>` を `<c:dLbls>` の
後**（スキーマ上は前が正）に出力する。PowerPoint は「読み取れないコンテンツ」として修復を要求し、
**修復の巻き添えでデータラベル設定等が書き換わる**（グレー系列に数値ラベルが出現した実例）。
LibreOffice / python-pptx は寛容なので④のレンダリング検証では検出できない。

- **対策（必須工程）**: ビルド直後に `scripts/sanitize_pptx.py output.pptx` を必ず実行する
  （冪等・チャート無しデッキに掛けても無害。`--check` で検査のみも可能）。
- §15（slideNumber の不正プレースホルダ）も同スクリプトが検出する（こちらは警告のみ、
  deck_helpers v3 の連番テキスト方式で回避済み）。

## 17. 上向き・左向きの線は負の extent になり PowerPoint 修復エラー（2026-07-13 実証）

`addShape(ST.line, {w: x2-x1, h: y2-y1})` で終点が始点より上（または左）だと、pptxgenjs は
**負の `<a:ext cy="-…">` をそのまま出力**する。OOXML の extent は正値必須
（ST_PositiveCoordinate）のため PowerPoint が修復を要求する。LibreOffice は寛容に描画するので
④のレンダリング検証では検出できない（リーダー線4本で実際に発生）。

- **対策**: deck_helpers v3 の `line()` は修正済み——`x/y=min、w/h=abs、flipH/flipV` の等価変換で
  常に正値を書く。生の `addShape` で線・コネクタを引くときも同じ正規化を必ず行う。
- `sanitize_pptx.py` にも防御実装済み（slides/layouts/masters/notesSlides の負 extent を
  flip 変換で矯正）。修復エラー3兄弟（§15 slideNumber・§16 チャートXML・§17 負extent）は
  すべて sanitize_pptx.py が検出・矯正する。

## 18. キーメッセージ28ptは全角33字が上限（2026-07-14 実測）

幅936ptのキーメッセージ枠に全角28ptは**約33字まで**。34字以上は折返して「1行厳守」が壊れる
（34字×3スライドがMAJOR差し戻しになった）。deck_helpers v3 の `chrome()` は33字超で自動縮小
（920/字数、下限20pt）＋`wrap:false` を実装済み。①outline段階でキーメッセージを33字以内に
収めるのが本筋（40字上限だった旧目安は28pt新スケールでは広すぎた——layout-grammar参照）。

## 19. normalize_icons.py の二重適用と、図形の描画順の上塗り（2026-07-14 実証）

- **normalize は再収集のたびに全体へ再実行しない**。旧版は透過済みPNGに再適用すると
  透明部が黒→輝度0→全面不透明化し「単色ベタ四角」に壊れた（17個全滅）。現行版は
  RGBA を白地合成してから処理する冪等実装＋原本は `assets/_opaque_backup/` に自動退避
  されるので、壊れたら backup から復元して1回だけ normalize する。
- **後から addShape/box したものが、先行して描いた「あらゆる要素」を上塗りする**。
  テキストだけの話ではない: 2026-08-05 に、箱の中に描いたはずの矢印＋ラベルが
  大箱（塗りつぶし）に完全に覆われて消えた（隠れたのではなく上塗り）。
  パネルの box より前に描いたラベルが切れて見える件（S1）も同じ原因。
  重なる要素は**背面→前面の順に描く**。
- **入れ子構造の図（箱の中に要素を置く）では順序を機械的に守る**:
  ①外側の箱 → ②箱の内部に置く矢印・ラベル → ③箱の中のノード、の順。
  「コネクタをまとめて先に描く」という整理の仕方をすると、後から描く箱に必ず食われる。
  レンダリングして**実際に見えていることを目視確認する**まで実装完了としない
  （コード上は addShape を呼んでいるので、構文チェックでは検出できない）。

## 20. bullet ＋ 複数ラン は組み合わせてはいけない（2026-08-05・4回手戻り）

pptxgenjs は `addText([...])` の**ラン1つごとに段落プロパティ `<a:pPr>` を出力**する。
このため「1つの箇条書き項目を複数ランに分ける」と、bullet の扱いが必ず壊れる。
4通り全部踏んだので結論だけ守ること。

| やり方                            | 結果                                                                                    |
| --------------------------------- | --------------------------------------------------------------------------------------- |
| run1 に bullet あり / run2 に無し | run2 が `buNone` を出し、**その段落の■が消える**                                        |
| run1・run2 とも bullet あり       | **段落が分割されて■が2個**になる（項目が途中で割れる）                                  |
| ■を本文に手で埋め込み bullet 無し | ■は出るが**ぶら下げインデントが効かず**、折返し行がマーカー位置まで戻って他項目とズレる |
| 1ラン内に `\n` を入れる           | **行ごとに新段落**が生成され、■が行数ぶん複製される                                     |

**唯一の安全な形**:

- **1項目 = 1ラン**。ラン内に `\n` を入れない（自動折返しに任せる）
- 項目の区切りは前のランの `breakLine: true`
- 全ランに**同一の bulletOpts** を渡す
- **「冒頭だけ太字」は諦めて、項目全体を太字にする**（部分強調のために割ると上の罠に落ちる）

```js
const bulletOpts = {
  fontFace: F,
  fontSize: 16,
  color: C.heading,
  bullet: { code: "25A0", indent: 16 },
  paraSpaceAfter: 8,
  lineSpacingMultiple: 1.2,
};
s.addText(
  [
    {
      text: "強調したい項目は全体を太字にする",
      options: { ...bulletOpts, bold: true, breakLine: true },
    },
    { text: "通常の項目", options: { ...bulletOpts, breakLine: true } },
  ],
  {
    x: IN(630),
    y: IN(110),
    w: IN(288),
    h: IN(268),
    fontFace: F,
    fontSize: 16,
    valign: "top",
  },
);
```

※ 色を部分的に変えたい場合（例: 「約0.25%」だけ赤）も同じ罠に落ちる。
その段落だけ**ネイティブ bullet を使わず**「■　」を本文に埋め込み、
`bullet: false` を明示したうえで**他項目とインデントが揃うか必ずレンダリングで確認**する。

## 21. 右カラム箇条書きの「高さ手計算」は破綻する（2026-08-05・3スライドで同時多発）

ContentText型の右1/3で「箇条書き4項目＋下部の示唆ボックス」を組むとき、
各項目のレンダリング高さを手計算して y を決め打ちすると**必ずどこかで外れる**。
実際に S16（項目が二重露光で判読不能）・S20・S21（4項目目が箱の下に完全に隠れる）で同時に発生した。
CJK の折返し行数は幅・フォント・約物の位置で変わるため、静的に見積もれない。

**対策（builder_brief にも記載）**:

- 箇条書きは**1つの `s.addText()` に breakLine ランを並べて自動フローさせる**。
  項目ごとに `T()` を呼んで y を積み上げない（重なりが原理的に発生しなくなる）
- 箇条書きブロックと示唆ボックスは**別図形として y 範囲を明確に分離**し、
  間に 10pt 以上のバッファを置く（例: 箇条書き y=110〜370 / ボックス y=382〜490）
- 幅288pt で 18pt は**1行あたり約14〜15字**しか入らない。4項目なら 16pt まで落とす
- 完了報告で**各要素の y 範囲を数値で列挙**させ、レンダリングで目視確認するまで完了としない

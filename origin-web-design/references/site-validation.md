# Site Validation Runbook（レンダリング実測 / コストあり）

サイト（HTML/web）を **実ブラウザで computedスタイルまで実測**して点検する手順。静的チェック
（`scripts/audit_html.py`）で取れない「CSS変数・継承・メディアクエリ適用後の実際の色」「フォーカスリングの
実表示」「テーマ切替後の各テーマ」を確認するために使う。

## 実行前の必須確認（コストゲート）

- **ブラウザ起動はコストがかかるので、必ずユーザーの承認を得てから実行する**（SKILL.md「Validateは人間に聞く」）。
- ユーザーが「毎回自動でvalidateして」と明示した場合のみ、都度確認を省く。
- ブラウザの選択・起動方針は `browser-automation-policy` Skill に従い、原則 `playwright-cli` Skill を使う。

## 手順

1. 対象を用意する: ローカルHTMLはローカルサーバ or `file://`、公開サイトはURL。
2. `playwright-cli` Skill でページを開く。
3. 実測チェック（JS評価で computed値を取得）:
   - **コントラスト**: 主要テキスト要素で `getComputedStyle` の `color` / 背景色を取得し、WCAG比を計算。
     背景が透過なら祖先を辿って実効背景を決める。4.5:1（大文字3:1）を満たすか。
   - **focus可視**: 主要インタラクティブ要素に `focus()` → `:focus-visible` のアウトライン/影が視認できるか。
   - **landmark / 見出し**: `main`/`header`/`nav`/`footer` の存在、見出し階層の飛びがないか。
   - **代替テキスト**: `img[alt]`・意味を持つ `svg[role=img][aria-label]` が揃っているか。
   - **ARIA / a11y**: 可能なら axe 相当の検査を実行（重大違反の有無）。
   - **テーマ切替**: テーマ切替UI（例: ライト/ダーク/高コントラスト）があれば、**各テーマに切り替えて上記を再測**。
     どれか1テーマでもコントラスト不足なら不合格。
4. 不合格は SKILL.md 手順11に従い最大2回まで修正 → 再測。
5. 結果（テーマごとのPASS/FAIL、実測値）を成果物の記録に残す。

## 静的との役割分担

- 構造系（lang/viewport/landmark/alt/focus-visibleの**存在**）→ 静的で十分。
- 実効値系（変数・継承・テーマ適用後の**実際の色**、フォーカスリングの**実表示**）→ 実測で確定。

静的で PASS でも、CSS変数やテーマ切替が絡むサイトは実測で最終確認する価値がある（過去に、静的は通るが
特定テーマだけコントラスト不足、というケースがあったため）。

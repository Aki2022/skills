## カタログとの関係

- `../2026-10-14.json` のカタログは、2026-10-14 版から作られ、`archive_sha256` は `562f1e19…` を pin している。2026年10月21日版の ZIP とは sha256 が一致しない。
- `scripts/tests/test_catalog.py` の `test_real_archive_has_all_560_headings` は、与えられた ZIP から生成した項目が、ZIP の見出し（foundations 8 文書・components 49 文書の h2/h3、560 件）と一致することを確かめる。カタログ pin との一致は確かめない。
- カタログの pin は 2026-10-14 版のまま据え置く（2026-11-07 判断）。2026年10月21日版から `catalog.py generate --previous` で再生成すると、項目 ID 566 件は全て一致し、新規・消失はゼロ。本文が変わるのは 19 件で、その 19 件は再分類が要る。再分類は TypeSafe の API 課金が出るため、承認を得てから `classify.py` で行い、その後に pin を移す。

## 扱い

- 上流の ZIP は、この repo に置かない。ライセンスを推定で扱う判断の後も、再配布はしない（2026-11-07 判断）。
- 出典は `../2026-10-14.json` の `attribution` に従う。デジタル庁が作成したものとして示さない。
- ZIP を一度含めたコミット（`3b7b49f`、main では `8a26bad`）は、履歴に残す（2026-11-07 判断）。PDL1.0 が適用されるなら、出典表記つきの再配布は認められるため、履歴は書き換えない。PDL1.0 が適用されないと確認された場合は、WS-20261012 と同じ手順で履歴から消す。
- デジタル庁への問い合わせは、2026-11-07 時点では行っていない。利用条件の確認が必要になったときは、問い合わせフォーム（https://www.digital.go.jp/contact）を使う。

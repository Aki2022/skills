# 媒体：LP（1 ページの Web）

## 構成の型（出発点）

まとまりの働き（辞書の 7 つ）で書く。主張は何回使ってもよい。

| 型 | 並び | 使う時 |
| --- | --- | --- |
| 結論から | 名乗り → 主張（効用） → 証拠と声 → 主張（不安への答え） → 提供条件 → 行動 → 出典と運営者 | 読み手が自分の課題に気づいている |
| 課題から | 名乗り → 主張（困りごと） → 事実 → 主張（効用） → 証拠と声 → 行動 → 出典と運営者 | 読み手が課題に気づいていない |

- A/B で差し替えるのは台本の要素：一番のメッセージ・まとまりの順序・文案など。別案は別の台本（完全なファイル）にして `variant_of: <基本の台本の id>` と、変える要素の鍵を `overrides`（例 `[blocks/blk-0001, blocks/blk-0002, messages/msg-0001]`）に宣言する。宣言していない違いは「交絡あり」の警告になる。`infoarch-author diff` で変わった要素を、`infoarch-author set` で set の id を確かめる。
- 最初の画面（名乗りと最初の主張のまとまり）に、一番のメッセージと行動喚起の入口を置く。
- 行動喚起は最後に加え、長いページでは途中にも置いてよい。
- 証拠と声のまとまりは、効用の主張の直後に置く。

## 器の目安

- まとまりは 5〜9 個（出典なし・目安）。入らないメッセージは削る。

## よくある失敗

- 最初の画面を、会社紹介や抽象的なキャッチコピーで使い切る。
- 証拠を最後にまとめて置き、効用との結び付きが切れる。

## 出典

- 結論を先頭に置く：Nielsen Norman Group（https://www.nngroup.com/articles/how-users-read-on-the-web/）。
- 型（AIDA・PAS など）：実務家の慣行で、効果の比較は逸話の域（出典なし・目安）。

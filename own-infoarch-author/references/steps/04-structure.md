# 段 4 構造を決める

目的：段 3 で選んだメッセージを、媒体の器に並べる。複数ページなら「どのページに何を置き、何と呼び、どう行き来するか」、1 つの制作物なら「どの順で並べるか」を決める。

## やること

1. 媒体のファイル（`media/` の該当ファイル）を読み、その媒体の構成の型を選ぶ。型は出発点で、依頼に合わせて変えてよい。
2. **1 つの制作物**：結論 → 根拠 → 証拠 → 行動 の順を基本にする。課題から入る型（課題 → 効用 → 証拠 → 行動）は、読み手が自分の課題に気づいていない時に使う。
3. **複数ページ**：ページごとに目的を 1 つにする。ラベル（ナビゲーションの語）は、同じ語を繰り返さず、読み手の言葉で書く。ページの集合は、読み手の行動の順に並べる。
4. 各セクションに `role`（problem / benefit / proof / how / objection / cta / vision / navigation / other）を付ける。行動喚起（cta）は最後だけでなく、長い成果物では途中にも置いてよい。

## よくある失敗

- 媒体の型を、依頼の目的を見ずにそのまま当てはめる。
- ラベルに社内の言葉（部署名・機能名の略称）を使う。読み手が探す語で書く。
- 1 ページに目的を 2 つ持たせる。

## アウトラインへの書き方

`pages[].id`・`pages[].label`・`pages[].sections[].role`。

## 出典

- 結論 → 根拠 → 証拠（ピラミッド原則）、導入の SCQA：Barbara Minto の Pyramid Principle の要約（https://thinkinsights.net/insights/minto-pyramid-principle）。原典は未確認。
- ラベルと構造の検証（ツリーテスト）：Nielsen Norman Group（https://www.nngroup.com/articles/tree-testing/）。

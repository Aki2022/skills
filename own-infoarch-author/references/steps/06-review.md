# 段 6 見直して渡す

目的：工場に渡す前に、outline が依頼と target に合っているかを確かめ、保存する。

## やること

1. `infoarch-author check` を走らせ、終了コード 0 にする（参照切れ・固定値の直書き・一番のメッセージの数・CTA・セクションと文案の対応・期限切れを直す）。IA_LEAD_UNSUPPORTED が出たら、一番のメッセージの提供価値に証拠が無い。証拠を positioning に足す提案をオーナーに出すか、一番を替える。
2. **最初の一目で一番が伝わるか**：順序が 1 のセクション（LP なら最初の画面、ポスターなら見出し、資料なら最初の結論のスライド）に、一番のメッセージを伝える文案が入っているかを確かめる。
3. 段 1 の行動が、CTA のメッセージ（`achieves`）として置かれているか確かめる。置かないなら `no_cta: true` で、報告に「CTA なし（意図）」が出る。
4. 声の「〜ではない」に当たる表現が無いか、文案を読み直す。
5. `outlines/<成果物 id>.yaml` に保存し、`infoarch-author set` で set の id を控えてから、工場（own-web-design など）に渡す。

## よくある失敗

- 検査が緑なことを、伝わることの証拠にする。検査は参照と形しか見ない。伝わるかは、描画した後の確認（最初の画面の判定）と人の判断で見る。
- 一番を最初の画面の外（スクロールの下）に置く。

## 出典

- 最初の一目で主題が伝わるかの確認：5 秒テストで分かるのは全体の印象で、文章は読めない（Nielsen Norman Group、https://www.nngroup.com/articles/testing-visual-design/）。秒数は出典なし・目安。

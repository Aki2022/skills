# 検査項目と閾値

`scripts/measure_lp.mjs` が判定する内容。**閾値を変えたらこの表と理由を必ず更新する。**
目の前のページが通るように黙って緩めるのは、検査を殺す行為。

## 失格レーン（決定論。exit 1）

| id                     | 判定                             | 既定                | なぜこの値か                                                                |
| ---------------------- | -------------------------------- | ------------------- | --------------------------------------------------------------------------- |
| `type-scale`           | font-size の種類数               | ≤ 8                 | 型どおりのスケールなら 6 前後に収まる。超えたら場当たりの指定が混ざっている |
| `line-height-scale`    | 適用済み行間の種類数             | ≤ 4                 | 本文・見出し・UI で 3 種が普通。増えるのは継承事故                          |
| `radius-scale`         | 角丸の種類数                     | ≤ 5                 | 3 段 + 円 + 例外 1。それ以上は形の言語が壊れている                          |
| `spacing-off-scale`    | 余白のスケール外の値             | 0 件                | 4px / 8px のうち多くの値を説明できる方を基準単位と推定し、割り切れない値を外れ値にする。基準を推定できない（トークン体系が無い）ページでは判定を見送る |
| `body-font-size`       | 本文（最頻サイズ）               | ≥ 15px              | 注記に引きずられないよう最頻値で見る                                        |
| `text-too-small`       | 全テキストの絶対下限             | ≥ 12px              | 注記でもこれ未満は読めない                                                  |
| `body-line-height`     | 本文の行間                       | ≥ 1.5               | 和文はこれを下回ると詰まる                                                  |
| `line-length`          | 80 文字超の段落の行長            | ≤ 48ch              | 和文の全角基準。欧文 65ch 相当。短い見出し・キャプションは対象外            |
| `contrast`             | CSS で背景が確定できる文字       | 4.5:1（大文字 3:1） | WCAG AA。**背景は透明を遡って合成する**（透明のまま比べると常に緑になる）   |
| `tap-target`           | 操作要素の寸法                   | ≥ 44px              | 文中のインラインリンクは WCAG 2.5.8 の例外として除外                        |
| `horizontal-scroll`    | ページの横スクロール             | 無し                | —                                                                           |
| `element-overflow`     | 画面外へのはみ出し               | 無し                | 横スクロール可能な祖先の中は除外（意図した内部スクロール）                  |
| `heading-jump`         | 見出し階層の飛び                 | 無し                | h2 → h4 等                                                                  |
| `heading-orphan`       | 見出し最終行の孤立               | ≥ 3 文字            | 1〜2 文字だけ折り返すと読みが崩れる                                         |
| `fold-h1` / `fold-cta` | ファーストビュー内に H1 と主 CTA | 収まる              | CTA は sticky があれば代替可                                                |
| `console-error`        | **自ホスト**の 4xx と JS エラー  | 0 件                | 第三者ホストは警告へ回す                                                    |
| `image-over-crop`      | `object-fit: cover` の切り取り率 | ≤ 0.45              | これを超えると意図した構図が画面に出ていない                                |
| `measurement-broken`   | 計測自体の破損                   | —                   | 未検証を緑に潰さないための番人                                              |

## 警告レーン（近似・環境差。exit に影響しない）

失格に混ぜない。混ぜると「常に赤い検査」になり、本物の欠陥が埋もれる。

| id                     | 状態                 | なぜ警告に留めるか                                                                 |
| ---------------------- | -------------------- | ---------------------------------------------------------------------------------- |
| `contrast-over-image`  | 画像の上の文字       | 背景の代表色を画素の最頻値で近似している。狭い箱では文字自身を拾う。**目視が要る** |
| `image-sunk`           | 絵が地に沈んでいる   | 閾値（焦点画素 200px²・明度差 20）が**未校正**。意図的に暗い写真で誤検知する       |
| `font-silent-fallback` | 宣言フォントが未読込 | headless の webfont 読み込みは実ブラウザと揺れる                                   |
| `image-unverified`     | 画素を取得できず     | 測れなかったことを報告する（緑にしない）                                           |

## 実装上、間違えやすい点（実際に踏んだもの）

1. **画素は必ずスクリーンショットで測る。** `img` を canvas に `drawImage` すると
   元画像を読むだけで、scrim・filter・重なりが反映されない。「実際にどう見えているか」
   を測れず、暗幕で潰れた絵を緑にしてしまう。
2. **背景色の解決順を間違えない。** 自分（や祖先）が不透明な面を持つなら、背後に
   画像が重なっていてもそれが背景。順序を逆にするとボタンの文字が誤検知になる。
3. **画像の上かどうかは DOM の親子でなく「重なり」で判定する。** 図版として並べた
   兄弟要素まで画素評価に回すと、ただの地の上の文字を誤検知する。
4. **焦点は分位で測れない。** 灯りのような焦点は全体の 1% 未満しか占めず、p99 でも
   拾えない。支配的明度からの乖離画素の**面積**で見る。
5. **`document.fonts.check()` は CJK webfont に使えない。** unicode-range で ~120 に
   分割されるため、任意の文字での判定が false を返す。「その family の FontFace が
   1 つも loaded でない」だけが確実に判る事実。
6. **未検証を `continue` で飛ばさない。** 飛ばすと合格に見える。警告として出す。
7. **行数は矩形数ではない。** `Range.getClientRects()` は*視覚的な行*でなく
   *インラインボックス*ごとに矩形を返す。実測では `<span>` と `<br>` を含む H1 が
   **2 行なのに 6 矩形**になり、最終行を 20.3 文字でなく 3 文字と誤認していた。
   矩形を `top` 座標でグルーピングすると視覚的な行に戻る。さらに
   要素高さ ÷ 行高でも行数を検算し、食い違うときは判定を見送る（誤検知より
   未検証を選ぶ）。**修正済み**。
   和文の分かち書き（「ふりかえり」が「ふりか／えり」に割れる等）は未検出のまま。
8. **遅延読み込みを確定させてから測る。** `loading="lazy"` の未読込を「壊れている」と
   誤判定する。
